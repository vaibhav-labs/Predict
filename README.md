# Predict

A 15-minute daily game that trains calibrated judgment: you stake a confidence on a claim, reality
scores you, and patterns of misses become lessons.

**Status:** Blocks 1 to 5 of 10 are built. Block 1, the Dial: the confidence call, the 240-question
starter bank, the baseline and Unit 1 practice, saved history with Export and Import, the calibration
curve, and the installable, offline-capable app shell. Block 2, the Journal: the prediction card with
its six-link chain, an offline checker, lock, resolve, and edge score against a hidden baseline. Block 3,
the Mirror: error bars and sample sizes on the calibration curve, the bias map by topic, domain and
horizon, level, streak and the seven-day score, the journal-only record, and the case file's "your
pattern" lens. Block 4, the Lesson Engine: pattern flags with a lesson, a drill and two re-tests, the note
after a miss, the sealed 200-call Unit 1 exam, and the autopsy with its rule card. Block 10, Compete (Units 10 to 12): a 1% dial scored by the sharp rule on tail questions with a sealed 400-call exam, a round-number pattern, several-outcome questions, Predict's own sealed forecast beside yours on world questions, and an Arena tracker for public questions on Good Judgment Open and Metaculus. Block 9, Know yourself (Units 7 to 9): a gut number before the chain, counter-argument and luck-or-judgment problems, a memory check that hides your record until you say what you remember, decision cards with a break-even and a review date, and a pattern for memory rewritten by the outcome. Block 8, Updating (Unit 6): update an open prediction with a logged reason, scored over its life at the number in force each day; evidence-stream problems (prior, news, your new number); two new patterns (frozen forecasts, whiplash). Block 7, Reasoning tools (Units 4 and 5): Fermi problems on a break-it-down worksheet, base-rate problems, reference-class ladders and probability chains, two sealed exams, four new patterns, and chain steps, an own-task tag and an outside-view grade in the journal. Block 6, Ranges (Unit 3): give a low and a high you are 90% sure of, scored against the reference interval of real cases, with a sealed 60-range exam. Block 5, the Coach: an optional private repository that holds your record, the weekly letter, drills and daily ideas from Predict (`design/coach.md`). `STATE.md` has the detail and the next step. The app is served by GitHub Pages at
https://vaibhav-labs.github.io/Predict/.

Everything personal stays off this repo. The code, tables and question bank are public; your calls,
predictions and coach letters live on your phone, and later in a private repo of your own.

## How it ships

A push to `main` runs `.github/workflows/pages.yml`: it checks the data tables and the question bank,
runs the engine tests, assembles `site/` from `app/` and `data/`, and deploys it to GitHub Pages. Setup is
one switch: Settings, Pages, Source: GitHub Actions. `.github/workflows/tests.yml` also plays the app in a
real Chromium on pull requests and pushes; it never blocks a deploy.

## Try it locally

```
python3 tools/check_data.py                  # tables and question bank (Python 3 only)
node --test tools/test_engine.mjs            # scoring, record and question draw (Node 22)
sh tools/build_site.sh                       # assemble site/
cd site && python3 -m http.server 8000       # then open http://localhost:8000
python3 tools/test_pwa.py                    # install, offline, update (needs Playwright and Chromium)
python3 tools/test_flow.py                   # the whole first-hour flow, about 3 minutes
```

## Re-run the evidence

```
sh sim/run_all.sh
```

Python 3 only, about a minute, and it needs the three helper scripts in `sim/tools/`. It re-runs the
scoring, economy, level and pacing simulations, validates the tables and rebuilds `design/balance-report.md`.

## Change a number

1. Edit `data/scoring.json` or a CSV. One value at a time.
2. Run `sh sim/run_all.sh`.
3. Read `design/balance-report.md`.
4. Log the change in `design/mechanics.md`, section 8.

## Change a question

The bank is generated. Edit a table in `data/question_tables/` or a generator in `tools/qbank/`, run
`python3 tools/make_questions.py`, then `python3 tools/check_data.py`, and commit the table and the
regenerated `app/content/questions/starter.json` and `exam-u1.json` together. A push whose bank does not
match its tables does not deploy.

To add a documented fact, add a row to `data/question_tables/base_rates.csv`: the source page, the number as
published (`doc_low` and `doc_high`, widened by `pad` for the source's rounding), the verbatim words or table row
that show it (`evidence`, which must contain both numbers), the day you read it, and the thresholds to ask about.
The checker rejects a threshold inside the documented range or too close to it. To add a record family, commit the
table, give it a row in `sources.csv`, write a generator in `tools/qbank/records.py`, and teach
`tools/check_questions.py` to re-derive it: a question the checker cannot re-derive fails the check.
